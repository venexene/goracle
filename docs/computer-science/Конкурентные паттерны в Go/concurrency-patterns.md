# Шаблоны конкурентного кода в Go

> **Проверено:** Go 1.27 · **Уровень:** стажёр — младший разработчик
> Эта глава посвящена композиции; синтаксис каналов и устройство планировщика вынесены в соседние темы.

Перед выбором шаблона определите владельца данных, предел конкурентности, порядок
результатов, реакцию на первую ошибку и условие завершения каждой горутины.

| Шаблон | Задача | Обязательное условие безопасности |
|---|---|---|
| пул обработчиков | ограничить число одновременно выполняемых задач | конечная очередь и отмена |
| разветвление | обрабатывать один поток несколькими исполнителями | безопасное разделение работы |
| объединение | собрать несколько потоков в один | закрытие после завершения всех отправителей |
| конвейер | связать последовательные этапы | каждый этап реагирует на отмену |
| группа ошибок | отменить соседей при первом сбое | все функции получают общий контекст |
| семафор | ограничить дорогой ресурс | освобождение разрешения на всех путях |
| «или завершено» | добавить отмену к чтению или записи | исключить навсегда заблокированную отправку |
| тройник | продублировать поток | определить поведение медленного потребителя |
| мост | превратить поток потоков в один | прекращать внутреннее чтение по отмене |

Буфер не исправляет отсутствие потребителя, а лишь откладывает блокировку. Не запускайте
горутины без понятного владельца и способа дождаться их завершения. Проверяйте отмену,
ошибку и медленного потребителя отдельными тестами под детектором гонок.

Подробные реализации: [полный справочник](reference.md). Связи с каналами,
синхронизацией и планировщиком показаны на [карте конкурентности](../concurrency-map.md).
