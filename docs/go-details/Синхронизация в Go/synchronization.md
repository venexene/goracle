# Синхронизация в Go: учебный маршрут

> **Проверено:** Go 1.27 · **Уровень:** стажёр — младший разработчик
> Прежний адрес сохранён; подробное устройство вынесено в справочное приложение.

**Перед чтением:** горутины, каналы и состояние гонки. **После маршрута:** вы
сможете выбрать атомарную операцию, блокировку или координационный примитив и
проверить инвариант детектором гонок. [Задания и самопроверка](../../practice.md#synchronization).

1. [Атомарные операции и модель памяти](atomics-and-memory-model.md).
2. [Блокировки](locks.md).
3. [Координация горутин](coordination.md).
4. [Конкурентные контейнеры](concurrent-containers.md).
5. [Полный справочник](reference.md).

Сначала устраняйте совместно изменяемое состояние владением данными. Если это не
подходит, выбирайте самый простой примитив с ясным инвариантом и проверяйте код через
`go test -race`. Отсутствие сообщения о гонке в одном запуске не является доказательством.

**Основные источники:** [модель памяти Go](https://go.dev/ref/mem) и документация пакета [`sync`](https://pkg.go.dev/sync).

## Краткий итог

- Сначала по возможности устраняют общее изменяемое состояние через владение данными.
- Блокировка защищает сформулированный инвариант, а не отдельную строку кода.
- Завершение горутин и порядок освобождения примитивов проверяют вместе с отменой.

Дальше: соберите решение из [шаблонов конкурентного кода](../../computer-science/Конкурентные%20паттерны%20в%20Go/concurrency-patterns.md).
