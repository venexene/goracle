# Версионный справочник сборщика мусора Go 1.27

> **Проверено:** Go 1.27.0
>
> **Перед чтением:** [вводная глава](garbage-collector.md), [фазы](phases-and-barrier.md) и [диагностика](diagnostics.md).
>
> **После чтения:** вы сможете найти реализацию фазы, регулятора или отладочного параметра в исходном коде Go 1.27.0.
>
> **Практика:** [задания и самопроверка](../../practice.md#garbage-collector).

Здесь собраны только детали, которые полезны для чтения диагностики и исходного
кода конкретной версии. Учебная модель находится во [вводной главе](garbage-collector.md),
фазы — в [главе о барьере записи](phases-and-barrier.md), а команды — в
[главе диагностики](diagnostics.md).

## Краткая карта реализации

| Область | Go 1.27.0 |
|---|---|
| Общая стратегия | конкурентная трассирующая маркировка и очистка, без поколений и перемещения объектов |
| Маркировка | Green Tea включён по умолчанию |
| Подходящие малые объекты | встроенные карты `marks` и `scans`, очередь спанов |
| Остальная работа | очереди отдельных объектов сохраняются и имеют более высокий приоритет |
| Барьер записи | гибрид Юасы и Дейкстры, локальный для P буфер `wbBuf` |
| Очистка | фоновая, помощь при выделении и принудительное завершение перед циклом |
| Возврат страниц | фоновый и синхронный очиститель страниц |
| Мягкий предел | `GOMEMLIMIT` или `debug.SetMemoryLimit` |

Аллокатор, размерные классы и спаны вынесены в актуальную главу
[«Аллокатор Go»](../Память%20в%20Go/allocator.md). Здесь они не дублируются.

## Цель кучи в реализации

Учебная формула и смысл её частей приведены в разделе
[«Цель кучи и GOGC»](garbage-collector.md#цель-кучи-и-gogc). В Go 1.27 функция
`heapGoal` дополнительно учитывает минимальную цель, мягкий предел, необходимое
расстояние для очистки и состояние текущего цикла.

При `GOGC=100` обычная минимальная цель равна 4 МиБ и масштабируется вместе с
`GOGC`; сборка с экспериментом `heapminimum512kib` меняет исходную величину на
512 КиБ. Это деталь версии, а не обещанная языком граница. Регулятор рассчитывает
более раннюю точку запуска, чтобы закончить маркировку около цели, поэтому значение
`/gc/heap/goal:bytes` нельзя трактовать как точный порог запуска.

## Фазы в терминах исходного кода

1. `finishsweep_m` завершает остаток предыдущей очистки.
2. Первая остановка мира подготавливает маркировку, включает барьер и помощь.
3. Рабочие `gcBgMarkWorker` и прикладные горутины выполняют маркировку.
4. `gcMarkDone` обнаруживает исчерпание распределённой работы.
5. Вторая остановка выполняет `gcMarkTermination`.
6. Мир запускается, а очистка идёт в фоне и на пути выделения.

Новый цикл при необходимости принудительно завершит неочищенные спаны. Крупное
выделение не имеет отдельного правила «сначала запустить сборку, затем повторить»:
оно проходит обычную проверку порога и может потребовать расширения кучи.

## Отладочные параметры

Актуальная форма строки `gctrace` и разбор полей находятся в
[главе диагностики](diagnostics.md#gctrace-снимок-одного-цикла). Формат относится к
диагностическому выводу конкретной версии и не предназначен для программного
разбора.

| Параметр | Значение в Go 1.27 | Назначение |
|---|---|---|
| `gctrace=1` | одна строка на цикл | краткое исследование циклов |
| `gcpacertrace=1` | внутренние решения регулятора | глубокая диагностика версии |
| `gcstoptheworld=1` | отключает конкурентную сборку | эксперимент |
| `gcstoptheworld=2` | также отключает конкурентную очистку | эксперимент |
| `scavtrace=1` | работа очистителя страниц | исследование возврата памяти ОС |
| `madvdontneed=0` на Linux | предпочитает `MADV_FREE` стандартному `MADV_DONTNEED` | сравнение поведения RSS |

`runtime.GC` запускает принудительный цикл и ждёт его завершения. Он не обещает
уменьшить RSS. `debug.FreeOSMemory` дополнительно принуждает очиститель страниц, но
тоже является диагностическим воздействием, а не способом исправить удержание
объектов.

## Краткий итог

- Справочник фиксирует реализацию Go 1.27.0, а не договор языка.
- Фазы, регулятор, барьер и очиститель находятся в разных частях `runtime`.
- Числовое или алгоритмическое утверждение следует проверять по тегу нужной версии.

## Продолжение

Для прикладного расследования вернитесь к [диагностике](diagnostics.md); справочник используйте для проверки конкретной детали реализации.

  приоритет очередей работы маркировки.

  [`runtime/mpagealloc.go`](https://github.com/golang/go/blob/go1.27.0/src/runtime/mpagealloc.go) —
  очиститель и карты свободных страниц.
