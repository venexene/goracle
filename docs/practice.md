# Практикум

Для каждой темы предусмотрены три уровня работы:

- **основа** — проверить понимание главного договора;
- **изменение** — доработать готовый пример и сохранить его свойства;
- **сценарий** — самостоятельно выбрать решение для небольшой прикладной задачи.

Готовые ответы намеренно не размещены рядом с условиями. Самопроверка должна
опираться на тест, измерение, схему или объяснение наблюдаемого результата.
Проверяемые исходники перечислены в `examples/coverage.json`.

## Разбор типичных неверных решений

| Ошибка | Почему возникает | Как исправлять и проверять |
|---|---|---|
| Горутина отправляет результат после ухода получателя | У отправки нет ветви отмены, а канал никто больше не читает. | Добавьте выбор между отправкой и `ctx.Done()`, затем проверьте остановку по ограниченному времени и запустите `go test -race`. |
| Созданный контекст не отменяется | Таймер и дочерние операции живут дольше нужного вызова. | Вызывайте полученную функцию отмены через `defer` у создателя контекста; в тесте дождитесь завершения зависимой операции. |
| Канал закрывает получатель или один из нескольких производителей | Сторона не знает, закончились ли все будущие отправки. | Назначьте одного владельца закрытия и дождитесь производителей через `WaitGroup`; проверьте случай конкурентного завершения. |
| Ошибка заменяется строкой или теряется | Верхний слой не может определить причину и выбрать действие. | Оборачивайте причину через `%w`, переводите её на границе слоя и проверяйте через `errors.Is` или `errors.As`. |
| HTTP-обработчик читает тело без предела | Клиент может заставить процесс выделить неограниченную память. | Ограничьте чтение до декодирования, запретите лишние поля и второй объект; проверьте каждую границу через `httptest`. |
| Повторяется отдельный SQL-запрос внутри уже нарушенной транзакции | Частичный результат первой попытки может сохраниться или транзакция останется непригодной. | Повторяйте весь сценарий в новой транзакции, ограничьте число попыток и проверяйте откат частично выполненной попытки. |
| Код усложняется ради предполагаемой скорости | Нет измерения, подтверждающего цену исходного решения. | Сначала сохраните исходный тест производительности или профиль, измените одну причину и повторите замер на тех же данных. |

<a id="capstone"></a>

## Сквозной проект

После тем HTTP, контекста, баз данных, журналирования и тестирования соберите
небольшую службу задач:

1. `POST /tasks` принимает один ограниченный JSON-объект;
2. прикладной сценарий проверяет данные и сохраняет задачу через интерфейс;
3. контекст запроса передаётся до хранилища;
4. журнал не содержит тела запроса и чувствительных данных;
5. сервер имеет сроки, мягко завершается и тестируется через `httptest`;
6. хранилище сначала реализуется в памяти, затем заменяется `SQLStore` с тестовой БД.

Эталонный каркас находится в `examples/taskservice`: в нём есть настройка сроков
сервера, хранилища в памяти и через `database/sql`, ограниченный обработчик,
журналирование и мягкое завершение. Расширяйте его по одному требованию и
сохраняйте успешное выполнение `go test -race ./...`.
