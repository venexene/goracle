# Миграции и тестирование базы данных

> **Проверено:** Go 1.27 · **Уровень:** младший разработчик

Несовместимое изменение выполняйте этапами: расширить схему, выпустить совместимый
код, перенести данные, переключить чтение и только затем удалить старое поле. Большую
операцию разделяйте на порции, чтобы не удерживать блокировку дольше допустимого.

Резервная копия считается рабочей после проверенного восстановления. Перед опасной
миграцией определите допустимую потерю данных, время восстановления и план остановки;
обратная миграция не всегда возможна без утраты новых данных.

Модульные тесты проверяют построение запросов и перевод ошибок. Интеграционные тесты
с настоящей версией СУБД проверяют миграции, ограничения, уровень изоляции и SQL-диалект.
Фиксируйте версию образа и не разделяйте состояние между параллельными тестами.

Подробнее: [миграции](reference.md#10) и
[тестирование](reference.md#17).
